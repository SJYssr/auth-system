# 软件商业授权落地路线

目标：让软件发行商完成“创建应用 → 配置销售方案 → 发卡 → 激活与设备绑定 → 心跳校验 → 到期续费 → 封禁与审计”。以真实客户端结果和数据库记录验收，不以页面数量或接口数量判断完成。

## 第一批：发货、续费与离线凭证（2026-10-18）

- 新增接口的应用归属边界：方案列表、设备绑定、产品列表、订单列表/详情/手动发货。初始化数据的应用、卡密统计同样按管理员隔离，公开网站信息不再包含 setup_token。
- 手动发货在同一数据库事务内完成：锁订单及产品、检查库存、按限时方案生成卡密、保留所属管理员、关联订单、扣库存。失败时全量回滚；已发货订单不能重复发卡。未接通的永久、多设备、并发、方案级离线及特性策略明确拒绝发卡，避免销售配置与实际权限不符。
- 卡密续费可在后台卡密列表操作。支持未到期叠加、已到期从当前时间起算、卡行锁、幂等请求编号、持久化续费流水、审计。禁用或未激活卡密不能新办续费。此接口属于管理员手工延长授权，不是支付自动续费。
- 离线凭证默认关闭。配置 `CARD_OFFLINE_HOURS` 为大于0且不超过24的小时数后，签发期限取“卡密到期、当前时间加离线窗口”的较早者。首次激活与同设备复登都返回正确凭证。
- 修正 PKCS8 DER hex 私钥加载及 Docker 密钥传入。新增 Node 客户端离线验签模块，要求使用内置可信公钥，并绑定应用ID和本机设备标识；拒绝篡改、到期、缺少期限及错设备凭证。
- 修正授权实例 ID 与 MySQL BIGINT 自增类型不一致的问题。后续生命周期实现见下。

## 第二批：卡密、授权与设备生命周期（2026-10-18）

- 首次激活在同一事务中写入卡密、授权实例、设备绑定和会话；任何一步失败都回滚。数据库约束阻止同一卡密生成重复授权和同设备重复有效绑定。
- 登录、心跳、到期查询与在线会话列表共同校验应用、卡密、授权状态、有效绑定及设备黑名单；有效期限取卡密和授权期限的较早者。
- 后台卡密列表新增设备操作及换绑历史。换绑同时修改卡密和授权、关闭旧绑定、创建新绑定并清除旧令牌；旧设备不能重新登录。解绑后，下一次成功登录绑定新设备。并发换绑按旧设备校验，只有一笔成功。
- 禁用、恢复、续费和删除同步处理授权状态。暂停或封禁的授权不能靠续费恢复；显式恢复卡密也不会恢复旧会话。通用卡密编辑不能绕过专用设备操作。
- 存量激活卡迁移时继承实际期限与状态；已有明确解绑记录的卡密清除旧会话，不恢复旧绑定。迁移支持重复启动。

## 可重复验收

先安装 server、client 和 e2e-test 的依赖，启动 Docker Desktop。执行：

```sh
npm --prefix server test
npm --prefix server run lint
npm --prefix e2e-test run test:commercial
E2E_LEGACY_SCHEMA=1 E2E_COMMERCIAL_UI=1 E2E_FULL_FLOW=1 npm --prefix e2e-test run test:commercial
```

商业验收脚本自动启动独立的 MySQL 8 容器，建立随机命名测试库，导入 schema 并执行迁移，使用真实后台会话、HTTP路由与数据库进行验证，结束后删除容器。不会读取现有项目数据库凭据。UI 模式还会先构建前端，再用 Playwright 点击续费、换绑并刷新、回读数据库。`E2E_LEGACY_SCHEMA=1` 验证存量数据迁移；`E2E_FULL_FLOW=1` 额外启动真实服务入口，执行原有卡密业务回归。首次运行需要 `mysql:8.0` 镜像，UI 模式需要已安装 Playwright Chromium。

重点验收：两名普通管理员的跨归属请求、列表与总数隔离、发货中途人为失败后的回滚、重复发货、库存耗尽、方案时长、首激/复登签名、旧令牌失效、到期拒绝、并发重复续费只延长一次、禁用卡不能续费、浏览器续费及刷新后的持久化。

这套验收覆盖真实 MySQL、HTTP和浏览器；尚不等同于生产反向代理、容器镜像、多实例和外部支付服务的部署验收。

## 存量数据库升级注意

升级前备份数据库，并使用副本演练。迁移013会给每个卡密添加唯一授权约束；遇到历史重复数据会停止，需按真实业务记录人工核对，不能直接删除以绕过约束。在升级副本中先检查：

```sql
SELECT card_id, COUNT(*) AS count FROM licenses
WHERE card_id IS NOT NULL GROUP BY card_id HAVING COUNT(*) > 1;
SELECT license_id, device_id, COUNT(*) AS count FROM license_device_bindings
WHERE unbound_at IS NULL GROUP BY license_id, device_id HAVING COUNT(*) > 1;
```

新库使用完整 schema；存量库通过启动迁移升级，不要重新导入 schema。数据库DDL可能已经部分生效，排除冲突后可重新执行迁移。旧卡密与已有授权的应用、设备信息不一致时客户端会拒绝授权，需要人工核查，不能自动放行。

## 后台续费接口

`POST /api/admin/cards/:id/renew`，使用管理员 Bearer 会话：

```json
{
  "duration_days": 30,
  "request_id": "a-client-generated-unique-request-id",
  "remark": "人工办理续费"
}
```

`duration_days` 为1到3650的整数；同一笔操作重试必须保留同一个 `request_id` 和内容。结果返回 `previous_expires_at`、`expires_at` 和 `replayed`。这是授权时长操作，不会自动收款。


## 后台设备操作接口

使用管理员 Bearer 会话，操作只允许资源所属管理员或超级管理员：

- `POST /api/admin/cards/:id/rebind`：`{"old_device_id":"原设备","new_device_id":"新设备"}`。
- `POST /api/admin/cards/:id/unbind`：`{"old_device_id":"原设备"}`。
- `GET /api/admin/cards/:id/device-history`：读取换绑历史。

操作要求卡密和授权均有效。旧设备必须匹配当前绑定，重复或过时请求会拒绝。在线令牌立即失效；已签发离线凭证仍受原离线窗口限制。本批实现单设备卡密；购买方案快照、多设备和方案级策略执行仍在待办中。
